# EM项目综合系统指南

## 📋 概述

本文档整合了EM项目的核心组件，包括MoCo多视图实现、注意力机制、三实体融合等关键功能的完整使用指南。项目支持灵活的命令行配置，可适应不同的实验需求和场景。

## 🏗️ 系统架构概览

```
EM (Embedding Model) System
├── 编码器层 (Encoder Layer)
│   ├── GATGTSerial - 图注意力+图变换器
│   └── 节点特征编码 [N, D] → [N, H]
├── 注意力融合层 (Attention Fusion Layer)
│   ├── AttentionFactory - 工厂模式创建
│   ├── 协作注意力 (Co-Attention) 
│   │   ├── PairwiseCoAttention
│   │   ├── TransformerPairwiseCoAttention

│   │   ├── SelfAttentionFusion
│   │   ├── CoAttentionFusion
│   │   ├── HybridFusion
│   │   ├── TransformerMultiHead
│   │   └── GatedTransformer
│   └── 三实体融合 (Tri-Entity Fusion)
│       ├── TriSelfAttentionFusion
```

## 📊 注意力机制详细指南

### 注意力类型对比

| 类型 | 特点 | 计算复杂度 | 适用场景 | 命令行配置 |
|------|------|------------|----------|-------------|
| **基础协作注意力** | 简单成对交互 | O(d²) | 小数据集、快速原型 | `--fusion_strategy co_attention` |
| **Transformer协作注意力** | 多头自注意力 | O(d²h) | 中等复杂度任务 | `--co_attention_type transformer` |
| **多头协作注意力** | 并行多头机制 | O(d²h) | 高维特征处理 | `--use_multihead` |
| **门控多头协作注意力** | 动态权重控制 | O(d²h+dg) | 精细控制需求 | `--headwise_gate` |
| **三实体自注意力** | 三元组统一建模 | O(H²) | 复杂三元关系 | `--tri_entity_mode True` |
| **三实体协作注意力** | 循环协作交互 | O(H²) | 多方强关联 | `--tri_fusion_strategy tri_co_attention` |

### 配置字符串语法

```bash
# 基础格式：type[param1=value1,param2=value2,...]

# 协作注意力示例
--attention_config "transformer[num_heads=8,dropout=0.1]"
--attention_config "gated_multihead[num_heads=4,headwise_gate=true,elementwise_gate=false]"

# 融合策略示例  
--attention_config "self_attention[heads=4,dropout=0.1]"
--attention_config "hybrid[fusion_weight=0.5,co_attention_type=transformer]"
--attention_config "gated_transformer[num_heads=8,headwise_gate=true]"
```

## 🔧 MoCo多视图配置详解

### MoCo类型选择

#### 基础MoCo (MoCoV2MultiView)
- **特点**: 简单高效，固定温度，环形队列
- **适用**: 标准对比学习，计算资源有限
- **配置**: `--moco_type basic`

```bash
python main.py --moco_type basic --moco_K 4096 --moco_T 0.2
```

#### 增强MoCo (EnhancedMoCoV2MultiView)  
- **特点**: 门控权重，自适应温度，GRU式更新
- **适用**: 复杂环境，噪声数据，精细控制
- **配置**: `--moco_type enhanced`

```bash
python main.py --moco_type enhanced \
  --moco_gate_hidden 128 \
  --moco_prune_threshold 1e-4 \
  --moco_decay_factor 0.99
```

### 高级MoCo配置

```bash
# 配置字符串方式（最灵活）
python main.py \
  --moco_config "enhanced[K=8192,gate_hidden=256,prune_threshold=0.0001,decay_factor=0.99]"

# 分参数方式（更直观）
python main.py \
  --moco_type enhanced \
  --moco_K 8192 \
  --moco_gate_hidden 256 \
  --moco_prune_threshold 0.0001 \
  --moco_decay_factor 0.99
```

### MoCo参数调优指南

| 参数 | 推荐范围 | 说明 | 调优建议 |
|------|------------|------|----------|
| `--moco_K` | 1024-8192 | 队列大小 | 小数据集用1024-2048，大数据集用4096-8192 |
| `--moco_T` | 0.05-0.5 | 温度系数 | 困难任务用0.05-0.1，简单任务用0.2-0.5 |
| `--moco_gate_hidden` | 32-256 | 门控隐藏层 | 简单任务用32-64，复杂任务用128-256 |
| `--moco_prune_threshold` | 1e-4-1e-2 | 剪枝阈值 | 噪声数据减小阈值，干净数据可增大 |

## 🎯 三实体融合机制

### 启用三实体模式

```bash
# 基础三实体模式（默认自注意力）
python main.py --tri_entity_mode True

# 三实体协作注意力
python main.py \
  --tri_entity_mode True \
  --tri_fusion_strategy tri_co_attention

# 三实体自注意力  
python main.py \
  --tri_entity_mode True \
  --tri_fusion_strategy tri_self_attention
```

### 实体抽取逻辑

| 任务类型 | 实体1 | 实体2 | 实体3 |
|---------|--------|--------|--------|
| **LDA** | `idx[0]` | `idx[1] + 240` | `idx[2] + 480` |
| **MDA** | `idx[0] + 645` | `idx[1] + 240` | `idx[2] + 880` |
| **LMI** | `idx[0]` | `idx[1] + 645` | `idx[2] + 1290` |

### 三实体 vs 两实体模式对比

| 特性 | 两实体模式 | 三实体模式 |
|------|------------|------------|
| **计算复杂度** | O(H) | O(H²) |
| **内存占用** | 基准 | 约1.5倍 |
| **建模能力** | 二元关系 | 三元复杂关系 |
| **训练速度** | 快 | 中等 |
| **适用场景** | 标准任务 | 复杂交互关系 |

### 混合使用场景

```bash
# 场景1: 两实体 + 协作注意力
python main.py \

  --fusion_strategy co_attention \
  --co_hidden_dim 128

# 场景2: 三实体 + 自注意力
python main.py \
  --tri_entity_mode True \
  --tri_fusion_strategy tri_self_attention

# 场景3: 三实体 + 协作注意力 + 增强MoCo
python main.py \
  --tri_entity_mode True \
  --tri_fusion_strategy tri_co_attention \
```

### 性能监控与调优

#### 监控关键指标
- **训练损失下降趋势**: 应该持续下降
- **验证损失稳定性**: 避免过拟合
- **AUROC提升**: 核心性能指标
- **内存使用**: 避免OOM错误
- **训练速度**: 平衡效果与效率

#### 常见问题诊断

**过拟合现象**:
- 训练损失持续下降，验证损失开始上升
- 解决方案: 减少模型复杂度、增加dropout、早停

**欠拟合现象**:
- 训练和验证损失都较高，AUROC提升缓慢
- 解决方案: 增加模型容量、延长训练时间、调整学习率

**训练不稳定**:
- 损失震荡较大，指标波动明显
- 解决方案: 调整学习率、增加梯度裁剪、使用学习率调度
